# Repeat-workout logging

Active sessions show the latest compatible, completed performance under each set. The reference includes the completed session date, actual reps or hold duration, actual load and effort. Imported program example loads are never treated as personal performance.

“Use previous load” fills only the current weight field. For composite source sets, “Use previous loads” fills the compatible repetition segments together. Current reps, seconds, effort and completion stay unchanged. The user must still complete the set to save it. Pure timed holds have no load-copy action. Completed, paused and saving rows disable reuse.

History requires the same account, exercise ID and set number. Sessions must have finished before the current session began. Incomplete sessions, ambiguous duplicate logs and invalid values are excluded. Source rows additionally require the same warm-up status and ordered movement labels, units and load multipliers in both the session snapshot and actual log. Changed movement structure therefore does not receive an unrelated previous load. Older compatible performance can be used when a newer session has no eligible record.

This is a reference and explicit input shortcut, not an initial-load prescription or automatic progression system. Source prescriptions, recorded history and nutrition equations are unchanged.

Validation covers source bench sets, a nine-part cable ladder, custom sets, pause/resume, explicit completion and reload persistence. Browser screenshots use actual UI interactions with isolated device-local test records; no test activity is seeded into the product.
